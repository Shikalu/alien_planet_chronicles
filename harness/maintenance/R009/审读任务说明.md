# R009独立首读任务说明

主笔：R009-main。授权：按harness修订301—400。各审者负责指定两个十章组，证据只写自己的Bxx目录，不改工作正文、正式正文、共享回填候选、旧报告或导航。此轮是实际独立首读，不是预设通过。

## 阅读顺序

1. 先按章顺序完整读指定工作稿（`异星录/06_执行计划/工作区/R009-Bxx/`），不得先读作者资料、旧审读报告或主笔解释。可先读AGENTS及写作/审读规范，因为其不替正文解释剧情。
2. 先写`reader-first.md`：逐章记录实际可确认的所在位置、目标/为什么必须行动、选择、变化、情绪回报、下章理由、首次卡顿原句及读者疑问。不得用后读资料代填首次感受。
3. 然后严格按AGENTS必读顺序读项目总纲、阅读地图、分卷及第四卷卷纲/十章卡/逐章卡、世界与角色规则、六份台账/术语（各文件当前已发生段和对应A21—A30范围及必要接口）、揭示与正文规范；核第四卷收官状态快照及相邻接口。记录实际来源范围，不宣称未读全文。旧章卡规划不覆盖已发生事实。301接口另核正式300和R008已发生回填，400接口核收官快照，不给401添加事实。
4. 必对照《正文与连载规范》第九节、《文风与细节精修规范》第二、七节、《黄金开篇与持续追读规范》。命中高频或AI腔模式必须有章号原句及针对性建议，不能只打勾。核数量、物件、伤势、消息来源、时日、光影/供能、参照系、真实代价、至少两项推进、两处反转前置、钩子轮换及逐章五项/每篇两项追读。

## 每组交付

- `initial.json`：schema_version=1, batch=R009-Bxx, writer, reviewer（采用父级给的真实审读标识）, independent=true, body_first=true, phase=initial, input_digest和source_digest均取该组initial-manifest.json；verdict仅pass或issues；issues逐项有id（如B31-01，跨章也唯一）、chapter、severity、quote（正文实际原句）、reader_problem、suggestion、status=open。无真实问题不造条目。
- `initial.md`：按AGENTS8.1格式；保留先正文后资料的发现差别、逐章所读确认、规范命中、吸引力/兑现问题及资料冲突。严格区分“角色猜测”“读者确认”“作者设定”。
- `suggested-edits.json`：以数组输出可直接给主笔审议的精确替换，每项`id, issue_id, chapter, path, old, new, reason`。old必须在该章唯一命中，优先整句/完整相邻段，不用机械全局去词；新句需解决实际因果与语言问题，不凭空增水/设备/人员/时间。可有多项替换关联同一问题。保证不重叠；预估改后2200—3200纯汉字，删长句后不足不能靠空话补字。
- `backfill-findings.json`：需要同步的原始台账/章卡问题与范围、原句、证据；可以提出精确old/new候选，不要只追加“以正文为准”。无变化可注明范围与理由。需要改变固定设定/已发生事实的争议标为conflict，不擅自改设定。

每组十章必须完整阅读。不要用词频脚本冒充审读，不模仿旧组通过文案。不要提前交final/pass追读报告。交付后等待主笔实际应用修订与封稿，再另轮重读复核、逐项闭环与52项追读报告。若本轮发现可影响后组的边界，精确列出并交父级协调。
